# PULSE simulations

**→ https://alexdtdm.github.io/pulse-simulations/**

An interactive walkthrough of how PULSE picks a receptivity distribution, built from
simulated interventions run against the PULSE MCP server.

## What is on the page

**Walkthrough** — pick a design (touchpoints per day, duration, arm, cohort size, daily
vulnerability fractions) and watch the touchpoint calendar fill in, one cell per call.
The colour of each cell is the distribution PULSE answered with: personalized, tailored,
intervention_specific or population. The arm plot shows the engagement decay the cohort
was drawn from, and the explanation below shows how the four groups nest inside one
another and how often each was used.

**Summary** — all 44 simulated designs in one table, ranked by how much of their calls
PULSE could answer from the narrowest group, with the day of the intervention each
distribution was first chosen. Click any column to re-rank.

## Reading it

Participants are synthetic (`SIM1`, `SIM2`, …) and so are their answers. Nothing here
comes from a real cohort.

Designs are not the same size — the smallest made 11 calls, the largest 660 — so a
percentage from a small run is a much weaker claim than the same percentage from a large
one. The Calls column is there to be read alongside the shares.

No run recorded a disease, so the `intervention_specific` column is really the "not
recorded" group. It measures cohort size, not disease.

## How it is built

A single self-contained HTML file: all data is embedded as JSON, nothing is fetched at
runtime, and there is no backend. `index.html` is generated by
`SIMULATION/build_how_pulse_works.py` in the simulation project, which reads the stored
runs, rewrites the data blocks and pushes the result here. GitHub Pages serves it from
`main`.
